Users

Sign-ins are created automatically when a party, lawyer, or judge is saved with an email and ID number (username = email, one-time password = ID). You can also create users manually here.

Microsoft 365 & Teams

Connect Microsoft 365 for cloud sync and email, and generate the Teams app package to run inside Microsoft 365. This is admin setup — staff and judges don't need it.

Add user

For court staff, judges, and administrators. To give a party, lawyer, or representative a sign-in, add them in the Registry instead (with their email + ID) — that creates and emails their sign-in for you.

Give the one-time password to the person privately — they will be required to replace it at first sign-in.

Sign-in server

Connect a sign-in server so people can log in from any device automatically — no publishing files. When a user is created with an email, the app emails them their login details (via the server, or your Microsoft 365 mailbox). Setup instructions are in SIGNIN-SERVER.md in the download.

“Publish case data” uploads this device’s cases so judges and parties can see them on their own devices. Do this once from an admin device after setup, and any time you want to force-refresh what everyone sees.

Publish config.json next to index.html once so every device (including parties) learns the server URL and can sign in. You only re-publish if the server URL changes.

No server yet? Use a published directory instead

Without a server, publish a static roster: it contains only usernames, roles and salted hashes — no case data or plain passwords.

Place it next to index.html; re-publish whenever you add users. Microsoft 365 sync also carries the roster between court devices automatically.

All users

Generate a fresh one-time password for many users at once — sets it on the sign-in server and emails it (if a mailbox is connected). Each person is asked to set their own password at next sign-in.
